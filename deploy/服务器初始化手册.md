# Travel OS 服务器初始化手册

> 本手册记录生产服务器（Ubuntu 24.04，腾讯云）从裸机到可接收 CI/CD 部署的完整步骤。
> 当前服务器 **已完成初始化**（2026-10-13），本手册用于重建或迁移新服务器时照做。

## 一、基础环境

已验证可用：Java 21（运行 Java 17 构建产物）、Nginx 1.24、Docker + Compose、Node 24。
缺失时安装：

```bash
sudo apt update
sudo apt install -y openjdk-17-jre-headless nginx docker.io rsync curl
sudo systemctl enable --now docker nginx
```

## 二、部署用户与 SSH

1. 本机生成部署密钥对：`ssh-keygen -t ed25519 -C travel-os-deploy -f travel_os_deploy`
2. 公钥追加到服务器 `/home/ubuntu/.ssh/authorized_keys`，验证密钥可登录
3. 确认 `ubuntu` 免密 sudo（`/etc/sudoers.d/` 中配置 NOPASSWD），CI 重启服务依赖此项

## 三、PostgreSQL（Docker）

国内服务器拉不了 Docker Hub，用腾讯云内网镜像：

```bash
sudo docker pull mirror.ccs.tencentyun.com/library/postgres:16-alpine
sudo docker tag mirror.ccs.tencentyun.com/library/postgres:16-alpine postgres:16-alpine

sudo docker run -d --name travel-os-postgres --restart unless-stopped \
  -e POSTGRES_USER=travel_os \
  -e POSTGRES_PASSWORD=<数据库密码> \
  -e POSTGRES_DB=travel_os \
  -p 127.0.0.1:5432:5432 \
  -v travel_os_pgdata:/var/lib/postgresql/data \
  postgres:16-alpine
```

注意：服务器 6379 已有原生 Redis（本项目后端用 Caffeine，不依赖 Redis）；3306 是原生 MySQL（本项目不用）；9000 是 Portainer。

## 四、数据库迁移

```bash
# 在仓库根目录打包迁移脚本并上传
tar czf migrations.tar.gz prisma/migrations apps/api-spring/db/migration
scp migrations.tar.gz ubuntu@<服务器>:/tmp/

# 服务器上按顺序执行（仅首次初始化需要 prisma/migrations 全量）
tar xzf /tmp/migrations.tar.gz -C /tmp/mig --strip-components=0
for f in $(ls /tmp/mig/prisma/migrations/*/migration.sql | sort); do
  sudo docker exec -i travel-os-postgres psql -U travel_os -d travel_os -v ON_ERROR_STOP=1 -f - < "$f"
done
sudo docker exec -i travel-os-postgres psql -U travel_os -d travel_os -v ON_ERROR_STOP=1 -f - \
  < /tmp/mig/apps/api-spring/db/migration/V20261013_01__add_users_deleted_at.sql
```

约定：**后续新增迁移只放 `apps/api-spring/db/migration/`，且必须幂等**（`IF NOT EXISTS`），
CI 每次部署会重放该目录全部脚本。`ALTER TYPE ... ADD VALUE` 不能包在事务里。

## 五、目录与环境变量

```bash
sudo mkdir -p /opt/travel-os/backups /var/www/travel-os
sudo chown -R ubuntu:ubuntu /opt/travel-os /var/www/travel-os
# 按 deploy/app.env.example 生成 /opt/travel-os/.env，chmod 600
```

## 六、systemd 服务

```bash
sudo cp deploy/systemd/travel-os-api.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now travel-os-api
# 首次需先放 jar：scp travel-os-api-*.jar ubuntu@<服务器>:/opt/travel-os/travel-os-api.jar
systemctl status travel-os-api
curl http://127.0.0.1:3000/api/health/database   # 期望 {"status":"ok","database":"connected"}
```

## 七、Nginx 站点

```bash
sudo cp deploy/nginx/travel-os.conf /etc/nginx/sites-available/travel-os
sudo ln -sf /etc/nginx/sites-available/travel-os /etc/nginx/sites-enabled/travel-os
# 原 80 端口的 Adminer 站点挪到 8001：
sudo sed -i 's/listen 80;/listen 8001;/' /etc/nginx/sites-available/adminer
sudo nginx -t && sudo systemctl reload nginx
```

## 八、GitHub Secrets

仓库 Settings → Secrets and variables → Actions，配置 5 个：

| Secret | 值 |
| --- | --- |
| `SSH_HOST` | 服务器 IP |
| `SSH_PORT` | 22 |
| `SSH_USER` | ubuntu（全小写） |
| `SSH_PRIVATE_KEY` | 部署私钥全文（含 BEGIN/END 行） |
| `VITE_API_BASE_URL` | http://<服务器IP>/api |

## 九、验证

- `http://<服务器IP>/` 打开前端
- `http://<服务器IP>/api/health` 返回 ok
- push 到 main 分支，Actions 中 deploy job 全绿
