# Travel OS 产品需求文档

| 项目 | 内容 |
| --- | --- |
| 版本 | v0.1，需求评审稿 |
| 盘点基准 | 2026-11-21 工作区源码、路由和交接资料 |
| 覆盖范围 | Travel OS Web、后端能力，以及独立仓库 Mappic 鸿蒙客户端的跨端边界 |
| 证据口径 | 「现状」指源码可见能力；「待核实」指尚无运行证据；「需求」指建议实施的目标行为 |

Travel OS 面向个人与可信同行者，帮助他们完成出发准备、途中执行和旅行归档。行程详情承担管理入口，移动端优先支持当天安排、导航、凭证和随手记账，公共攻略承担内容发现和复制。首页优先回答「下一步做什么」。

现阶段最优先的是让跨入口的权限、金额和日期规则一致，并确保跨端未同步编辑可恢复。随后再降低出发现场的操作成本。本文是需求基线，线上运行、弱网、真机能力和全量回归需要单独验收。

## 1 用户与主流程

| 角色 | 主要任务 | 权限要求 |
| --- | --- | --- |
| 行程所有者 | 建立行程、邀请成员、设置可见性、管理和交接所有权 | 转让、删除、公开等动作应展示影响并二次确认；服务端验证权限 |
| 行程管理员 | 协助排程、管理成员与账目 | 允许的操作以行程角色为准，敏感操作应有记录 |
| 普通成员 | 按权限编辑安排、记账、上传照片或写游记 | 共享行程权限和个人内容的可见性分别判断 |
| 观察者 | 查阅被授权的行程内容 | 共享内容只读；个人收藏属于个人偏好，不修改团队数据 |
| 好友或广场读者 | 阅读授权游记、浏览和复制攻略 | 仅接触发布范围及允许复制的字段 |
| 平台管理员 | 查看服务指标、管理账户状态和排查异常 | 管理员身份与行程角色分开；敏感数据访问须遵循明确规则 |

| 阶段 | 推荐主流程 | 完成标志 |
| --- | --- | --- |
| 旅行前 | 创建草稿 → 补日期与目的地 → 排程 → 添预订与清单 → 邀请同行 | 用户知道出发时间、首日安排及仍待准备的事项 |
| 旅行中 | 首页或移动端进入当天 → 查看路线、地址、凭证 → 勾选完成并记账 | 弱网下能判断哪些内容可用；失败操作有明确恢复路径 |
| 旅行后 | 完成行程 → 核对分摊并结算 → 分类整理照片与游记 → 选择归档、导出或发布 | 结算口径可解释，发布范围和导出范围明确 |

| 跨页能力 | AI 助手、宠物、今日简报、地图地点联想、天气、模板、PDF、文件授权、审计与提醒任务 | AI 草稿确认、外部依赖降级、只读或确认后写入、导出字段范围（TR-05、TR-08、TR-12、TR-15） |

## 3 需求与验收标准

P0 处理授权、财务正确性和数据完整性问题。P1 改善核心流程和使用反馈。P2 为需要产品取舍或适合后置的能力。优先级为本次评审建议。

### P0 数据与权限

| ID | 现状与问题 | 目标行为 | 验收标准 |
| --- | --- | --- | --- |
| TR-01 游记可见性一致 | 首页按行程成员和非草稿条件取最近游记，并返回摘要；游记服务另行判断私有、好友及指定受众，行程成员资格与游记授权并不等价。源码确认 | 首页、游记列表、导航、详情和关联图片各自使用一致的授权规则；首页先过滤再取最近三条 | 两人同为行程成员但无游记访问权限时，首页响应和界面均不出现私有游记的标题、摘要或入口；指定受众有权查看；撤销后读不到；草稿始终只对作者可见 |
| TR-02 费用与结算币种 | 首页人民币汇总已修复；行程费用汇总和结算仍对多币种加总，今日简报也累加当日金额后附单一币种。源码确认 | 明细保留原币，汇总按币种分组，预算标明币种；按原币生成各自的结算，不隐式换算。分币种结算上线前，混币快照需拦截并说明 | `100 CNY + 100 USD` 分别显示两笔原币金额；结算、今日简报、预算与报表没有虚假的 `200` 单币种金额；历史快照保留且标记其原始口径；小数和分摊尾差守恒 |
| TR-03 改期与日期关联 | 部分更新只验证本次提交的日期字段。缩短日期时，只用地点和预订判断某天是否有内容。可能影响已挂接费用、照片或游记的天；具体删改结果需用库约束复测 | 合并原值和新值后验证日期；修改前列出受影响的天与关联资源。保留或迁移有内容的天需走明确规则 | 只更新开始日也不能产生倒序。无日期草稿可以保存。若缩短范围涉及地点、预订、费用、照片、游记，用户确认前不移除这些关联；操作失败可恢复到原状态 |
| TR-04 鸿蒙同步保护 | 云端加载成功会保存服务端副本；编辑上传失败仅保留本地缓存等待下次保存，下一次读取可能覆盖待上传编辑。源码路径确认，真机待验 | 同步明确显示待上传、失败及冲突，并保留未上传编辑。上云以账户和行程隔离，冲突提供重试或选择版本 | 断网编辑、杀进程重开、重连后修改仍可见并能重试；同一地点被两端修改时保留两份变化线索；重复重试不重复创建；切换账号不会看到上一账号缓存 |

### P1 核心体验与任务闭环

| ID | 现状与问题 | 目标行为 | 验收标准 |
| --- | --- | --- | --- |
| TR-05 日期、时区与状态 | 首页按服务端默认时区确定今日，简报选择使用账户时区，模板摘要中的上午下午又回到固定时区。统计年份基于行程开始日。源码确认 | 区分行程日历日期、预约时刻、用户显示时区；首页与简报对今日和行程状态采用相同规则。统计年份口径可见 | 在北京时间跨日、目的地跨时区、跨年三种样例中，首页、今日简报、预约时间及统计各按声明的规则显示；进行中行程优先显示今天；无日期草稿不会出现虚假倒计时 |
| TR-06 首页和详情导航 | 首页同时承担出发看板、AI 入口、地图和回忆；新用户、旅途中和旅后需要的第一步不同。属流程评估 | 根据无行程、草稿、即将出发、旅行中、旅后显示一个主要动作。待办、清单、地图和简报保留各自来源，入口定位到对应行程或日期 | 无行程可在首页创建；有进行中行程时可直接打开当天；简报不可用时仍能进入安排和凭证；无小计数据说明原因而非显示误导性的 0 |
| TR-07 出行速查与地图 | 地图有外部 SDK 及降级路线，凭证需访问对应行程。时长格式分别取整小时和分钟，存在分钟进位异常。弱网场景待验 | 当天地点、地址、关键凭证优先可达；标点可用时地图可先展示，并标明路线仍在计算或已降级。打印及可选离线保存以最低必要信息为默认 | 模拟地图故障仍能复制地址及查看当天列表；时长分钟恒为 00–59；区分真实驾车路线和示意线；离线副本如纳入范围，须显示保存时间、权限边界和清除入口 |
| TR-08 协作与模板 | 成员、好友、编辑锁、审计和模板已有入口，权限与编辑反馈分散。属流程评估 | 按角色在当前页面显示可用操作、锁持有人或重试提示；邀请易理解；应用模板前说明新增和保留内容 | 观察者无法保存共享编辑；成员被移除后刷新或再次请求即失权；编辑冲突保留未提交输入；同一模板重复应用不会无提示覆盖现有安排 |
| TR-09 个人收藏 | 收藏字段存于共享行程并更新该行程的更新时间，可能改变其他人的排序。源码确认 | 收藏按用户和行程保存，内容更新时间独立；团队置顶如有需求单独定义 | 同行 A 收藏或取消后，B 的收藏和排序不变；收藏本身不修改行程正文最后编辑时间；历史共享收藏迁移策略有记录 |
| TR-10 预订转费用 | 已支持预订与费用关联。取消、退款、删账再转及并发提交的体验需统一，不能只从入口存在断定闭环 | 展示预估、已入账、取消和退款状态；重复确认复用同一业务结果。预算清楚标出预计占用与实际支出 | 重试或连点只产生一笔有效关联费用；已转费用不再重复占用预估；取消、退款及删除关联费用后的处理有明确结果 |
| TR-11 结算快照及变更 | 支持结算计算和确认存档；结算后补记、成员退出和历史对账需明确产品契约 | 确认前展示期间、参与者和币种。快照可追溯，后续修改生成新的待结算差异；离队成员的历史欠款能被正确归属 | 三种分摊可对账；补记或改账保留原快照；成员退出后历史记录与应收应付仍能解释；应收等于应付 |
| TR-12 发布、分享和附件 | 攻略、游记和凭证已有不同的发布与分享入口；凭证「分享行程」复制当前 URL，链接不等于增加访问权限。源码确认 | 分享界面明确谁能打开。攻略发布前预览可见字段，凭证区分原始可核验码和用于速查的信息码；默认按最小可见范围控制附件、预览、打印和 PDF | 非成员收到私有凭证链接仍受原权限限制；公开攻略和复制结果不出现证件号、确认码、费用明细或私有附件；修改可见范围后当前访问结果同步变化 |
| TR-13 导出与注销 | JSON 由浏览器逐行程聚合，子请求失败会回填空值，照片与文档只导出元信息，用户可能误以为是完整备份。源码确认 | 导出前说明数据范围和是否含附件；文件内记录格式版本、缺失模块及失败原因；注销前说明保留与共享数据处理方式 | 模拟文档请求失败时，导出明确为部分完成并列出缺项；页面可重试失败项；改密、注销、导出和共享行程归属符合确认文案 |
| TR-14 偏好与通知 | 可存主题、时区、单位、货币及通知开关。静态搜索中多项通知字段只出现在存储和设置展示，实际消费需逐项核验 | 每项偏好列出作用范围。已接入的开关须影响对应事件；未接入的选项标注为待开放或收起。通知发送去重，失权后的跳转给出清楚提示 | 分别验证行前、文档、成员邀请和摘要开关，明确哪些已生效；同一事件不会重复提醒；SSE 断开后轮询仍能更新未读数 |
| TR-15 AI 边界 | 有会话、流式、任务限额、草稿确认、简报模板降级和宠物入口。用户需要知道草稿写入范围和错误后如何恢复 | 摘要区分数据事实与建议；应用前预览对象及变更；失败可取消或重试。模型、天气和地图不可用时保留手工路径，默认不发送证件和凭证的敏感值 | 无模型时仍可使用手工行程和模板简报；重复应用同一个草稿只写入一次；权限撤销期间无法应用；生成失败时能区分超时、额度和第三方异常 |
| TR-16 管理后台降级 | 平台总览直接读取 CI 汇总，CI 文件缺失或解析失败会导致该读取返回 503。源码确认 | CI 状态卡单独降级并标明来源或更新时间；用户总览和用户管理独立可用 | 去掉 CI 数据、写入无效 JSON 时，平台用户与行程总览仍可访问；CI 卡明确提示暂不可用；非管理员无法访问管理接口 |

### P2 产品取舍

| ID | 决策点 | 建议与验收 |
| --- | --- | --- |

## 4 发版顺序与验收

| 批次 | 范围 | 出口条件 |
| --- | --- | --- |
| A 权限与关键数据 | TR-01、TR-02、TR-03；Mappic 若作为主力端则同批纳入 TR-04 | 使用独立数据验证成员可见性、币种结算、改期关联与同步冲突，结果进入回归套件 |
| B 旅行当天 | TR-05、TR-06、TR-07、TR-08、TR-09、TR-10、TR-11、TR-12 | 在桌面和移动端完成从当日安排到凭证、导航、记账的主流程，以及旅行后结算和受控分享 |
| C 账户与支撑 | TR-13、TR-14、TR-15、TR-16、TR-17 按实际收益拆批 | 依赖故障能独立降级，导出范围和设置效果可解释；AI 变更可审查与追溯 |

验收覆盖三类账号（所有者、同行、无授权读者），以及无日期草稿、跨时区、多币种、改期、账户切换、弱网与外部服务错误。关键操作须记录可观察结果，包括响应数据、页面状态、数据库最终状态及夹具清理。涉及 Mappic 的条目须在真机验证，构建、改动覆盖与回归结果分别记录。

建议先记录操作基线，再设目标。优先观测从首页找到当天安排和凭证所需步骤、记账成功率、跨端未同步操作的恢复率、同一笔费用在各入口的金额一致性。验收门槛包括未授权样例没有敏感内容返回、混币用例没有错误合计、改期和同步故障场景没有静默丢失编辑。现有发布回滚、CI 运行与 E2E 收尾继续以项目复核清单登记，独立于产品功能验收。

## 5 待确认的产品决策

| 决策 | 建议默认值 | 影响 |
| --- | --- | --- |
| 行程日期与时区的权威来源 | 行程日期按目的地当地日历，账户时区用于展示和通用提醒；跨时区预订保留原时区 | 首页、简报、行程天、预订、统计 |
| 何时允许归档 | 允许用户主动归档，无未完成结算时可直接归档，有待处理项时先提示 | 行程列表、提醒、对账 |
| 证件和凭证离线范围 | 默认只准备当天必要信息，敏感原件需主动选择并提供清除 | 弱网、共享设备与移动端 |
| 默认币种与预算口径 | 个人默认币种作为录入初值，行程预算采用独立明确币种，历史明细保持原币 | 费用、简报、预算、统计 |
| 公共攻略保留方式 | 优先设定发布字段白名单与预览；是否引入独立发布快照按撤回和历史保留需求决定 | 游记、广场、文件访问、复制 |
| 多端首发边界 | 鸿蒙首发优先确保日期、地点与费用可可靠同步，再决定是否扩展凭证和照片 | 移动端与接口兼容 |
