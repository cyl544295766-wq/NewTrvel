# 路线图

## 已完成能力

| 模块 | 已实现 |
| --- | --- |
| 账户 | 注册 / 登录（Bearer + Cookie 双通道）、账户状态校验、软删 |
| 行程 | 列表、签发、编辑、归档、收藏、复制、删除、封面、预算 |
| 协作 | 成员与四种角色（owner/admin/member/viewer）、邀请、角色变更 |
| 行程安排 | 按日期批量生成行程天、地点增删改与排序、完成勾选、天标题内联编辑 |
| 地图 | 高德地图标点、每日真实驾车路线与里程时长、按天聚焦、卫星底图 |
| 费用 | 记账、三种分摊（均分 / 按比例 / 按金额）、分类与预算、报表图表、结算快照与转账方案 |
| 打包 | 分类清单、模板物品自动填充、勾选进度与完成印章 |
| 预订 | 5 类预订（机票 / 酒店 / 火车 / 门票 / 其他）、类型特有字段、出发提醒 |
| 凭证 | 出行现场速查凭证（大字信息格 + 二维码 + 打印 / 分享） |
| 证件 | 证件与票据归档、到期预警、提醒开关 |
| 照片 | 多选上传、按行程天分组、拼贴与网格视图、封面、说明编辑 |
| 游记 | 撰写（心情 / 草稿 / 关联照片）、卷首大卡、沉浸式阅读排版与上下篇导航 |
| 统计 | 年度维度的行程与费用统计、图表、年份下钻 |
| 通知 | 聚合、时间分组、类型筛选、已读管理；预订与证件到期自动推送 |
| AI 助手 | 行程级对话（OpenAI 兼容协议），未配置时自动降级为关闭 |
| 导出 | 行程 PDF 导出、账户数据 JSON 导出 |

## 当前状态

- 前端 **19 个页面**全部落地，均有端到端脚本覆盖（`tools/e2e/`）
- 服务端 **21 个 Controller / 22 张表**，覆盖上述全部能力
- 生产部署链路（GitHub Actions → COS 中转 → 服务器）已跑通

## 已知待办

| 项 | 说明 | 影响面 |
| --- | --- | --- |
| 高德 Web 服务 Key | `AMAP_WEB_SERVICE_KEY` 未配置，`/api/places/suggestions` 返回 503 | 行程安排添加地点时的联想输入降级为纯手输；需另申请「Web服务」类型 Key |
| 账户偏好设置 | 主题 / 时区 / 单位 / 默认货币等偏好缺服务端接口 | 账户页已留位并标注「待接入」，控件禁用 |
| 账户资料编辑 | 修改密码、修改显示名与头像缺接口 | 同上 |
| 注销后数据清理 | `UserCleanupScheduler` 已预留（默认关闭） | 需先确定保留期限策略再启用 |
| 地点类型与费用类别的完整支持 | 数据库枚举取值多于前端配色映射的子集 | 前端遇未知值回落默认样式，功能不受阻 |
| 行程默认应用模板 | 打包与行程天的模板化生成 | 提升新行程的创建效率 |

## 产品约束

- **Trip 是核心业务实体**，任何新模块都必须直接或间接挂在 Trip 之下
- 实现功能前，先确定数据库、业务流程、API、页面结构
- 前端保持零构建，服务端保持单进程同源托管
